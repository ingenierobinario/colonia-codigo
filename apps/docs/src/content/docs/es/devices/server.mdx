El core anda perfecto solo. Ponelo en un VPS chico o en una compu que esté siempre prendida, y tus agentes siguen
trabajando (rutinas, canales, tareas) mientras tu notebook duerme. La app de escritorio y tu teléfono se conectan a él.

Nada de esto necesita root, y el servidor no necesita tener Node instalado: el paquete trae el suyo.

## 1. Instalar

<Tabs>
<TabItem label="Linux y macOS">

Corrélo en el servidor (se instala donde se corre), por SSH:

```bash
curl -fsSL https://colonia.ingenierobinario.com/install.sh | bash -s -- --server
```

O desde tu propia computadora en una sola línea, también desde PowerShell en Windows:

```bash
ssh usuario@servidor 'curl -fsSL https://colonia.ingenierobinario.com/install.sh | bash -s -- --server'
```

Opciones: `--file <paquete>` (un paquete que ya tenés, sin descargar), `--version <x.y.z>`, `--feed <owner/repo>`,
`--no-service`, `--uninstall`. Por el pipe van después de `bash -s --`, por ejemplo
`curl -fsSL https://colonia.ingenierobinario.com/install.sh | bash -s -- --no-service`.

```bash
bash install.sh --file colonia-core-<version>-linux-x64.tar.gz
```

</TabItem>
<TabItem label="Windows">

En PowerShell:

```powershell
& ([scriptblock]::Create((irm 'https://colonia.ingenierobinario.com/install.ps1'))) -Server
```

Parámetros: `-Server`, `-File <paquete>`, `-Version <x.y.z>`, `-Feed <owner/repo>`, `-NoService`, `-Uninstall`.

</TabItem>
<TabItem label="Desde la app de escritorio">

No hace falta abrir una terminal en el servidor. En el primer arranque de la app de escritorio (o en el menú Colonia ›
Cambiar conexión):

<Steps>

1. Elegí **Cliente**, después **SSH**, y escribí `usuario@servidor`. Usa tu propio `ssh` y tus claves.

2. Si Colonia todavía no está en ese servidor, la app te lo dice y te ofrece **Instalarlo por mí** (o **Instalarlo a
   mano**, que te muestra el comando). Manda el mismo `install.sh` por SSH e instala la versión de la propia app.
   Funciona en servidores Linux y macOS; en Windows, instalalo a mano.

3. En Linux después te pide que Colonia siga corriendo cuando te desconectes, un paso que necesita al administrador del
   servidor: **Hacerlo por mí** te pide la contraseña de sudo (va directo a `sudo` por SSH y no se guarda), o **Lo
   hago a mano** te muestra el comando. Después se conecta y sigue con la configuración de tu crew.

</Steps>

</TabItem>
</Tabs>

Qué hace el script:

- Baja el paquete de Colonia más nuevo para tu sistema y lo verifica contra su `.sha256`.
- Lo descomprime en `~/.colonia/v2/app/versions/<version>/` y apunta `~/.colonia/v2/app/current` a esa carpeta. La versión que
  corría antes queda hasta la próxima actualización.
- Escribe el comando `colonia` en `~/.local/bin` (y suma esa carpeta al archivo de arranque de tu shell si no estaba en el
  `PATH`).
- Si tenés Colonia v1 instalado, frena su daemon y saca su comando `colonia`. Sus archivos en `~/.colonia` quedan, para que puedas
  importarlos.
- Arranca el core como servicio, salvo que hayas pasado `--no-service`.

Tus datos viven en `~/.colonia/v2`, aparte de la app.

## 2. Configurarlo

Un solo comando termina de preparar el servidor:

```bash
colonia setup --headless --expose tailscale     # o --expose lan
```

Sumá `--import` (con `--keys`, `--skills` y `--services` si los querés) para traer los proyectos y agentes de un Colonia v1
en la misma máquina.

Corre, en orden, los mismos pasos que podrías hacer a mano:

<Steps>

1. **Correr el core como servicio.** `colonia service install` escribe una unidad de usuario de systemd (Linux), un agente
   de launchd (macOS) o una entrada de inicio de sesión (Windows), arranca el core y espera a que responda. Vuelve a
   arrancar al iniciar sesión y cada vez que se cae.

2. **Importar Colonia v1** (solo con `--import`). Lo mismo que `colonia import-v1`. Solo lee los archivos de v1.

3. **Exponer el core** (solo con `--expose`). Lo mismo que `colonia expose tailscale` o `colonia expose lan`, seguido de
   `colonia service restart`, porque el core lee su configuración al arrancar.

4. **Vincular un dispositivo.** Lo mismo que `colonia pair`: muestra un código de un solo uso, las direcciones y un enlace
   `colonia://pair`.

</Steps>

<Aside type="caution" title="Linux: que siga corriendo cuando cerrás sesión">
Un servicio de usuario de systemd se frena cuando cerrás tu sesión en el servidor. Activá el linger una vez (necesita
`sudo`). El instalador lo hace solo cuando sudo no pide contraseña; si no, te muestra esta línea, con tu usuario:

```bash
sudo loginctl enable-linger <usuario>
```
</Aside>

Revisalo cuando quieras:

<Terminal command="colonia service status">{`service  systemd: active
core     answers on http://127.0.0.1:7440`}</Terminal>

En Linux, el log del core está en el journal: `journalctl --user -u colonia -f`. En macOS y Windows está en
`~/.colonia/v2/logs/core.log`.

## 3. Elegir quién puede llegar

Por defecto el core solo le responde a su propia máquina. `colonia expose` cambia eso:

Loopback impide el acceso directo desde Internet; no separa a los usuarios del mismo sistema operativo. Sin token,
un proceso local puede controlar el core. En un servidor compartido, usá una cuenta dedicada y autenticación.
Colonia administra una crew del mismo dueño: vincular un dispositivo concede acceso de operador, no acceso de invitado.

| Comando | Qué hace |
|---|---|
| `colonia expose tailscale` | Deja el core en `127.0.0.1` y lo publica con `tailscale serve` en `https://<machine>.<tailnet>.ts.net`, alcanzable solo desde tu tailnet. |
| `colonia expose lan` | Hace que el core escuche en todas las direcciones (`COLONIA_HOST=0.0.0.0`), por ejemplo `http://192.168.1.20:7440`. |
| `colonia expose off` | Vuelve a solo esta compu. El token queda. |
| `colonia expose status` | Qué está en vigor, el puerto, si hay token y dónde está el archivo de configuración. |

Tanto `tailscale` como `lan` crean un token para el core si no tiene, y lo muestran una sola vez. Después reiniciá el
core (`colonia service restart`) para que lea el cambio.

<Aside type="tip" title="¿Tailscale o red local?">
Para un VPS, elegí **Tailscale**. El core nunca escucha en una dirección pública, el tráfico va por https y solo los
equipos de tu tailnet pueden llegar. Tailscale tiene que estar instalado y con la sesión iniciada en el servidor, con
MagicDNS prendido; si `tailscale serve` falla, puede que tengas que habilitar HTTPS para tu tailnet en el panel de
administración de Tailscale.

**Red local** es http sin cifrar en todas las direcciones de la máquina. Usala solo en una red en la que confíes (tu
casa, tu oficina), o poné tu propio proxy con TLS adelante. Nunca en un servidor con IP pública.

En cualquiera de los dos casos, cada pedido de afuera necesita el token del core o la llave de un dispositivo
vinculado. El core se niega a escuchar en una dirección que no sea loopback sin `COLONIA_TOKEN`, y rechaza un pedido que
llega a través de un proxy cuando no tiene token.
</Aside>

`colonia tailscale status`, `colonia tailscale connect` y `colonia tailscale off` hacen lo mismo para Tailscale a través del core
que está corriendo, como hace el panel en **Configuración › Conexiones › Dispositivos**.

### core.env y el token

`colonia expose` escribe `<home>/core.env` (`~/.colonia/v2/core.env`, salvo que `COLONIA_HOME` diga otra cosa), que solo vos podés
leer (modo 600). Solo puede definir estas claves: `COLONIA_HOST`, `COLONIA_PORT`, `COLONIA_TOKEN`, `COLONIA_PUBLIC_URL`,
`COLONIA_ALLOWED_ORIGINS`. Después de `colonia expose tailscale` queda así:

```ini
# Colonia core settings (KEY=VALUE). Written by `colonia expose`; the process environment wins over this file.
COLONIA_TOKEN=<64 caracteres hexadecimales>
COLONIA_PUBLIC_URL=https://<machine>.<tailnet>.ts.net
```

Las variables de entorno del proceso le ganan al archivo. El comando `colonia` y la app de escritorio en la misma máquina
leen el token de acá solos, así que no tenés que copiarlo a ningún lado. Los otros dispositivos nunca lo reciben: se
vinculan.

## 4. Conectar tus dispositivos

Corré `colonia pair` en el servidor cada vez que necesites un código (sirve una vez, por 10 minutos).

<Terminal command="colonia pair">{`Pairing code: ABCD2345
Expires at 10:40:00 (in about 10 min)

Addresses a device may reach this core on:
  https://<machine>.<tailnet>.ts.net

In the Colonia app, open Pair and paste the link, or enter an address and the code:
  colonia://pair?c=ABCD2345&u=https%3A%2F%2F<machine>.<tailnet>.ts.net`}</Terminal>

- **App de escritorio**: en el primer arranque elegí **Cliente**, y después **Dirección** (la de Tailscale o la de la
  red local; el panel te pide el código) o **SSH** (`usuario@servidor`). SSH usa tus propias claves y trae el core a tu
  compu, así que anda aunque el servidor no esté expuesto a nadie. Detalles en [App de escritorio](/es/devices/desktop/).
- **Teléfono**: escaneá el QR desde el panel, pegá el enlace `colonia://pair` en la app de Colonia, o abrí la dirección en el
  navegador del teléfono y escribí el código. Mirá [Tu teléfono](/es/devices/phone/).
- **Un navegador en otra compu**: abrí la dirección del core (la de Tailscale, o la de la red local, como
  `http://192.168.1.20:7440`). El panel te pide **Vinculá este dispositivo**: escribí un código de `colonia pair` (o de
  **Configuración › Conexiones › Dispositivos › Vincular un dispositivo** en un dispositivo ya vinculado), y ese
  navegador se guarda su propia llave. No hay que instalar nada en esa compu.

Cada dispositivo tiene su propia llave. Revocá uno con `colonia devices revoke <id>` o en **Configuración › Conexiones ›
Dispositivos**.

Instalar Colonia en el VPS por una terminal SSH no registra tu computadora como nodo. La app de escritorio conectada
por SSH sí presta su navegador al core mientras mantiene esa conexión. El control de pantalla, teclado y mouse
requiere activar **Uso de la computadora**. Al cambiar conexión o cerrar la app, deja de prestar esas capacidades.
Abrir una dirección del servidor en un navegador no presta automáticamente las capacidades de tu computadora.

## Actualizaciones

Una instalación con el paquete se actualiza sola. Cada 6 horas (la primera vez, un minuto después de arrancar) el core
le pregunta a los GitHub Releases de `ingenierobinario/colonia` si hay un Colonia más nuevo. El panel lo muestra en la barra
de arriba, sea que lo abras en el servidor o desde una app de escritorio conectada a él, y **Actualizar ahora** baja el
paquete nuevo, verifica su `.sha256`, lo descomprime al lado del que está corriendo, mueve `current` y reinicia el core.

Desde la terminal:

```bash
colonia upgrade --check     # ¿hay un Colonia más nuevo?
colonia upgrade             # aplicarlo
```

Volver a correr el script de instalación también instala la versión más nueva. `COLONIA_UPDATES=off` frena los chequeos;
`COLONIA_RELEASES=<owner/repo>` los apunta a otro origen (`off` también los frena).

## Desinstalar

```bash
curl -fsSL https://colonia.ingenierobinario.com/install.sh | bash -s -- --uninstall
```

Frena el servicio y borra `~/.colonia/v2/app` y el comando `colonia`; tus datos en `~/.colonia/v2` quedan. En Windows, guardá
`install.ps1` y correlo con `-Uninstall` ([Desinstalar](/es/start/install/#desinstalar)).

## Desde el código, en cambio

En una máquina donde trabajás en Colonia:

```bash
pnpm install
alias colonia="node $PWD/apps/terminal/src/main.ts"
colonia service install
```
