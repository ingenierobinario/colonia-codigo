`colonia` es la terminal de Colonia. No tiene lógica propia: cada comando es una llamada al core que está corriendo, las mismas
que hace el panel. Así que todo lo que haces aquí lo puedes hacer también en el panel, y casi todo al revés.

`colonia --help` muestra la lista completa. `colonia tasks help` y `colonia routines help` muestran el detalle de esos dos grupos.

<Aside type="tip">
Lo que va entre ángulos lo completas tú: `<id>` es un id que sale del comando que lista eso (`colonia agents`,
`colonia threads`, `colonia tasks`…), `<agent>` el id de un agente, `<project>` el de un proyecto.
</Aside>

## La consola interactiva

Ejecuta `colonia` sin argumentos en una terminal interactiva (o `colonia wizard`) y tienes una consola con autocompletado con Tab
e historial:

| Comando | Qué hace |
|---|---|
| `/status` | Core, equipo y proyectos (igual que `colonia status`). |
| `/devices` | Dispositivos vinculados. |
| `/tailscale` | El acceso por red y el estado de Tailscale. |
| `/connect` | Expone Colonia por Tailscale. |
| `/pair` | Un código para conectar un dispositivo nuevo. |
| `/updates` | Busca un Colonia más nuevo. |
| `/panel` | La dirección del panel web. |
| `/help`, `/quit` | El menú de nuevo; volver a tu shell. |

Los números del `1` al `6` son atajos de las opciones del menú y el `0` sale. Fuera de una terminal (un script, un
pipe) la consola no arranca: `colonia` muestra la ayuda.

## Estado y mantenimiento

| Comando | Qué hace |
|---|---|
| `colonia status` | La versión y el commit del core, cuánto lleva prendido, memoria, URL, cada subsistema, el equipo, los proyectos, los servidores MCP, los dispositivos, el acceso y los chats. También `colonia --status`. |
| `colonia --version` | La versión y el commit de esta CLI (`-v`). Funciona sin el core. |
| `colonia ping [text]` | Una ida y vuelta por el socket en vivo. |
| `colonia open` | Abre el panel en tu navegador. |
| `colonia desktop` | Abre la app de escritorio (la primera vez baja y abre el instalador). |
| `colonia wizard` | Configuración y mantenimiento guiados en la terminal. |
| `colonia upgrade --check` | ¿Hay un Colonia más nuevo? |
| `colonia upgrade` | Aplicarlo, igual que **Actualizar ahora** en el panel. Si el core no responde, un Colonia instalado con el script de instalación se actualiza igual: baja el paquete más nuevo, lo verifica y hace que el servicio lo arranque. `colonia update` es el mismo comando. |
| `colonia doctor` | Por qué el core no responde en este ordenador (qué dice su log, el servicio, si hay una versión más nueva) y el comando a correr. Funciona sin el core; `--json`. |
| `colonia logs` | Las líneas más nuevas del log del core, a través del core: `-n 200`, `--level info\|warn\|error`, `--grep texto`, `--scope core\|output`, `--json`. Si ningún core responde, el archivo de este ordenador. |
| `colonia service logs` | El archivo de log de este ordenador (`<home>/logs/core.log`); `-n 100`, `-f` para seguirlo. |
| `colonia daemon` | Explica qué comando `colonia service` usar (el core en segundo plano ahora es un servicio). |
| `colonia --help` | La lista completa (`-h`). |

`colonia status`, `colonia devices`, `colonia tailscale status`, `colonia upgrade`, `colonia mcp tools`, `colonia mcp check` y `colonia memory`
aceptan `--json`. `colonia status --plain` saca la tarjeta y el retrato.

## Servicio, acceso y dispositivos

| Comando | Qué hace |
|---|---|
| `colonia service install` | Corre el core en segundo plano: una unidad de usuario de systemd (Linux), un agente de launchd (macOS) o una entrada de inicio de sesión (Windows), que arranca al iniciar sesión y de nuevo si se cae. |
| `colonia service status` | Si el servicio está instalado y corriendo, y si el core responde. |
| `colonia service restart` | Lo reinicia (el core lee `core.env` al arrancar). `colonia service start` hace lo mismo, o lo instala si todavía no está instalado. |
| `colonia service uninstall` | Saca el servicio. |
| `colonia expose tailscale` | Publica el core en tu tailnet en `https://<machine>.<tailnet>.ts.net`; el core queda en loopback. |
| `colonia expose lan` | Escucha en todas las direcciones de red de esta máquina. |
| `colonia expose off` | De nuevo solo este ordenador (el token queda). |
| `colonia expose status` | Qué está en vigor, el puerto, el token (si hay o no) y el archivo de configuración. |
| `colonia tailscale [status]` | El estado de Tailscale y el modo de acceso, preguntándole al core. |
| `colonia tailscale connect` | Expone Colonia por Tailscale (tiene que tener la sesión iniciada). |
| `colonia tailscale off` | Vuelve al acceso local. |
| `colonia pair` | Un código de un solo uso, las direcciones y un enlace `colonia://pair` para un teléfono u otro ordenador. |
| `colonia devices [list]` | Dispositivos vinculados. |
| `colonia devices pair` | Igual que `colonia pair`. |
| `colonia devices revoke <id>` | Revoca la llave de un dispositivo. |
| `colonia setup --headless` | Un servidor sin escritorio: servicio, importación opcional (`--import`), exposición opcional (`--expose tailscale` o `--expose lan`) y después un código para vincular. |
| `colonia import-v1` | Registra las carpetas de proyecto que conoce un Colonia v1 local (solo lee v1). `--keys` también copia sus claves de API de modelos, `--skills` sus skills, `--services` sus motores de imágenes y voces. |
| `colonia v1` | ¿Sigue Colonia v1 aquí y corriendo? `colonia v1 off` detiene su daemon para siempre y hace que `colonia` sea este. |

`colonia expose` edita `<home>/core.env` directamente; después reinicia el core (`colonia service restart`). `colonia tailscale`
pasa por el core que está corriendo, que se reinicia solo cuando corre bajo un supervisor como el servicio, y si no te
avisa que lo reinicies. Más en [Colonia en un servidor](/es/devices/server/).

token    none (the core only accepts this computer)
settings ~/.colonia/v2/core.env (none yet)`}</Terminal>

## Chats y corridas

| Comando | Qué hace |
|---|---|
| `colonia chat "<text>"` | Habla con Home (la secretaria) y mira la respuesta mientras se arma: pasos de herramientas, subhilos, widgets, preguntas. |
| `colonia chat "<text>" --agent <id>` | Habla con un agente, en su última conversación contigo (`--new` arranca otra). |
| `colonia chat "<text>" --thread <id>` | Escribe en un hilo puntual. |
| `colonia chat "<text>" --code` | Un hilo de código en el proyecto registrado que contiene la carpeta actual (`--cwd <folder>` para otra, `--write ask`, `auto` o `read-only`, `--agent <id>`). |
| `colonia threads [list]` | Los hilos con su estado y tipo. |
| `colonia threads get <thread>` | Los últimos 20 mensajes de un hilo. |
| `colonia threads search <words…>` | Mensajes con todas las palabras, el mejor resultado primero. |
| `colonia threads cancel <thread>` | Frena lo que esté corriendo ahí. |
| `colonia runs get <run>` | Una corrida, en JSON. |
| `colonia runs wait <run>` | Espera a que termine (`--timeout 60`, en segundos). |
| `colonia runs pending [thread]` | Lo que los agentes esperan de ti: confirmaciones y preguntas. |
| `colonia runs respond <input> approve` | Aprobar (o `deny`), con una nota opcional y `--scope once`, `session` o `always`. |
| `colonia runs respond <input> "<answer>"` | Responder una pregunta. |
| `colonia jobs [list]` | El trabajo en segundo plano que corre ahora y los últimos 10 terminados. |
| `colonia jobs get <job>` | El estado y la salida de un trabajo. |
| `colonia jobs cancel <job>` | Lo frena. |
| `colonia compact <thread>` | Resume ya los turnos viejos de un hilo (el loop propio de Colonia). |
| `colonia notifications` | Lo que te está esperando. |
| `colonia notifications read` | Marca todo como leído. |
| `colonia news` | Las novedades que trae Colonia: si ya se contaron y si te aplican. |
| `colonia news tell [id…]` | Contar novedades ahora (esas de nuevo, o las que te aplican y faltan), con las palabras de tu super-agente. |

`colonia chat` también acepta `--detach` (manda y vuelve sin esperar), y `--interrupt` o `--steer` para cuando el agente ya
está trabajando (frenarlo, o meter el mensaje en el turno que corre). Sin esas opciones, el mensaje espera su turno.

— completed · thread home`}</Terminal>

## Agentes y proyectos

| Comando | Qué hace |
|---|---|
| `colonia agents` | Los agentes y el modelo con que corre cada uno (★ marca a Home). |
| `colonia agents show <agent>` | Sus campos y su prompt completo. |
| `colonia agents new <slug> "<Name>"` | Un agente nuevo; `--project <id>` lo pone en un proyecto (se escribe en `.apc/agents/<slug>.md`), `--role "<role>"` le da un rol. |
| `colonia agents set <agent> key=value…` | Cambia cualquier campo del editor de agentes (uno desconocido los lista todos). Listas como `tools=web_search,shell` (`tools=` es todas), `orchestrator=true`, `rules='{"write":"ask"}'`; `autonomy=` o `rules=` vuelven al valor por defecto. |
| `colonia agents set <agent> --prompt-file <file>` | Reemplaza su prompt desde un archivo (`-` lee stdin). |
| `colonia agents limits [<agent> runs=… tokens=… \| <agent> clear \| default runs=… tokens=…]` | Hasta dónde avanzan los agentes sin ti en un chat: el valor por defecto y el presupuesto propio de un agente (`0` = sin límite). |
| `colonia agents clone <agent…>` | Copia agentes a un proyecto (`--project <id>`); `--rename` le da a cada uno un nombre libre, `--under <slug>` fija el padre. |
| `colonia agents archive <agent>` | Archiva un agente (el archivo de un agente de proyecto pasa a `.apc/agents/.archived/`). |
| `colonia agents archived` | Agentes archivados; `colonia agents restore <agent>` trae uno de vuelta. |
| `colonia agents model <agent> <ref>` | Su modelo: `<engine>/<model>`, `<engine>`, `router` o `default`; `--router` deja el router como respaldo. |
| `colonia projects [list]` | Los proyectos (un `!` marca una carpeta que no está). |
| `colonia projects register <folder>` | Registra una carpeta con `AGENTS.md` y/o `.apc/`. |
| `colonia projects create "<Name>"` | Un proyecto nuevo, en `--path <folder>` (se crea si falta) o en una carpeta propia en el home de Colonia; `--kind personal\|app\|company\|software\|other`, `--desc "…"`. |
| `colonia projects set <project>` | Cambia `--name`, `--kind`, `--desc` o `--autonomy manual\|auto\|accept_edits\|plan\|total` (hasta dónde llegan sus agentes sin preguntar). |
| `colonia projects folders list\|add\|rm <project> [folder]` | Carpetas que sus agentes pueden leer y nunca cambiar (otro checkout, documentación): `file_read` y `shell` leen ahí, nada escribe. |
| `colonia projects rm <project>` | Lo olvida en Colonia; su carpeta y sus archivos nunca se borran. |
| `colonia init [folder]` | Convierte una carpeta (esta por defecto) en un proyecto APC y la registra; solo escribe lo que falta (`AGENTS.md`, `.apc/`). |
| `colonia projects sync [project]` | Vuelve a leer los archivos del proyecto. |

## Modelos y consumo

| Comando | Qué hace |
|---|---|
| `colonia models` | Cada motor y los modelos que ofrece (`--refresh` les vuelve a preguntar). |
| `colonia models config` | El predeterminado de la instalación, la cadena del router y sus reglas. |
| `colonia models default <ref>` | El predeterminado: `<engine>/<model>`, `<engine>` o `router` (`--router` para dejar el router de respaldo). |
| `colonia models chain <ref> [<ref>…]` | La cadena de respaldo del router, en orden. |
| `colonia models rules < rules.json` | Las reglas del router, como un array JSON por stdin. |
| `colonia usage [days]` | Turnos y tokens por modelo en los últimos días (30 por defecto), y si entraron en un plan o se pagaron por token. |
| `colonia image "<prompt>"` | Dibuja una imagen y la guarda (`--out <file>`, `--size WxH`). |
| `colonia say "<text>"` | Dice un texto en voz alta y guarda el audio (`--out <file>`). |
| `colonia transcribe <audio file>` | De voz a texto. |
| `colonia owner [set key=value…]` | Quién eres para tus agentes: nombre, sobre ti, idioma, zona horaria. |
| `colonia org [set] --project <id>` | Las áreas y roles de un proyecto (`set` lee JSON por stdin). |
| `colonia profiles [list]` | Para qué sirve el super-agente. `use <id> [key=value…]`, `off`, `restore <routine>`. |

Qué es una referencia de modelo y el router está en [Modelos](/es/concepts/models/).

## Oficina

| Comando | Qué hace |
|---|---|
| `colonia tasks` | Las tareas abiertas por columna (`--project <id>` para un proyecto). |
| `colonia tasks add <title…>` | Una tarea nueva: `--project <id>`, `--agent <id>` (asignarla), `--due 2026-10-05`. Con `--person <name> --owed me` o `--owed them` es un compromiso. |
| `colonia tasks commitments` | Lo que debes y lo que te deben. |
| `colonia tasks move <id> <column>` | La pasa a otra columna. |
| `colonia tasks done <id>` | La cierra como hecha (también `drop` y `reopen`). |
| `colonia tasks say <id> <text…>` | Un comentario; un `@agente` en el texto le pregunta a ese agente ahí. |
| `colonia routines` | Las rutinas y cuándo corren (`--project <id>`). |
| `colonia routines add <name> <prompt…> --agent <id>` | Una rutina nueva. Horario con `--cron "30 8 * * 1-5"`, `--every 60` (minutos) o `--at <fecha ISO>`; sin ninguno es a mano. También `--project`, `--pre "<command>"`, `--post "<command>"`, `--call always`, `output`, `fails` o `never`. |
| `colonia routines run <id>` | La corre ya. |
| `colonia routines on <id>` | La prende (`off` la apaga). |
| `colonia routines rm <id>` | La borra. |
| `colonia routines log <id>` | Sus últimas corridas. |
| `colonia flows run <flow> ['<JSON>']` | Corre ahora un flow publicado; uno con webhook recibe el JSON como cuerpo. No corre dentro del comando de un agente. |
| `colonia flows stop <flow> <evento>` | Detiene una ronda que está corriendo; un mensaje o llamada ya mandados quedan para revisar. No corre dentro del comando de un agente. |
| `colonia memory [words]` | Las notas que guardan los agentes, de la más nueva a la más vieja, o las que mejor coinciden con las palabras (`--project`, `--agent`, `--json`). |
| `colonia memory add [scope] <text>` | Agrega una nota. El alcance es `global`, `project` o `agent` (con `--project <id>` o `--agent <id>`); sin alcance sigue esas opciones, y si no, `global`. |
| `colonia memory edit <id> <text…>` | Reescribe una nota en el lugar. |
| `colonia memory rm <id…>` | Borra notas. |

En una rutina, la salida del pre-comando llega al prompt donde escribas `{{pre_output}}`. Más en
[Tareas](/es/office/tasks/), [Rutinas](/es/office/routines/) y [Memoria](/es/concepts/memory/).

## Canales y contactos

| Comando | Qué hace |
|---|---|
| `colonia channels` | Los canales y su estado. |
| `colonia channels add telegram <id> --agent <agent>` | Agrega un bot de Telegram. El token sale de `COLONIA_CHANNEL_TOKEN`, nunca de la línea de comandos. |
| `colonia channels rm <id>` | Borra un canal y su token. |
| `colonia channels outbox` | Lo que se mandó últimamente y cómo salió. |
| `colonia channels send <channel> <contact> <text…>` | Le escribes tú a un contacto, en su chat de ese canal. |
| `colonia channels recover <thread>` | Le vuelve a pedir al canal los archivos que nunca llegaron a un chat (WhatsApp: tu teléfono vuelve a mandar esos mensajes; tiene que estar en línea). |
| `colonia contacts` | Las personas y sus direcciones. |
| `colonia contacts add <name…>` | Agrega un contacto. |
| `colonia contacts block <id>` | Bloquea a una persona (`unblock` para deshacerlo). |
| `colonia contacts rm <id>` | Borra a una persona. |
| `colonia pairing` | Desconocidos esperando aprobación. |
| `colonia pairing me <code>` | Esta dirección es mía (del dueño). |
| `colonia pairing ok <code> [name…]` | Aprobar como contacto. |
| `colonia pairing no <code>` | Rechazarlo. |

Los demás canales (WhatsApp, Discord, Slack) se configuran en el panel. Mira [Canales](/es/channels/overview/).

## Skills, MCP, extensiones y secretos

| Comando | Qué hace |
|---|---|
| `colonia skills [project]` | Las skills que pueden cargar los agentes. |
| `colonia skills on\|off <skill>` | Activa o desactiva una skill en todos lados, o en un proyecto (`--project <id>`). |
| `colonia skills save <skill>` | Crea o reemplaza una skill: su `SKILL.md` por stdin (`--project <id>`). |
| `colonia skills install-runtimes` | Actualiza ya las skills que le enseñan a Claude Code, Codex, Cursor y `~/.agents` a usar Colonia (el core también lo hace en cada arranque). `--dry-run` muestra qué cambiaría. |
| `colonia mcps [list [project]]` | Los servidores MCP, con su estado y cantidad de herramientas. |
| `colonia mcps add <name> <command…>` | Agrega uno propio: un comando con sus argumentos, o una URL. |
| `colonia mcps rm <name>` | Lo saca. |
| `colonia mcps show <name>` | Su definición (las variables salen como `secret://NAME`, nunca sus valores). |
| `colonia mcps set <name> --env K=V` | Cambia solo lo que pasas (`--env`, `--header`) y deja el resto. |
| `colonia mcps on\|off <server> --project <id>` | Activa o desactiva uno de tus servidores dentro de un proyecto. |
| `colonia mcps logs <server>` | Lo que un servidor imprimió por stderr desde que arrancó el core (`--project`, `-n 100`). |
| `colonia sessions projects codex\|claude` | Proyectos y chats de Claude Code o Codex en este ordenador. |
| `colonia sessions import codex\|claude <project>` | Los trae como un proyecto de Colonia (`--only <id,…>`, `--name "…"`); también `digest`, `adopt` y `page`. |
| `colonia mcps trust <project> <server>` | Aprueba un servidor que nombra el `.apc/mcps.json` de un proyecto (`untrust` para deshacerlo). |
| `colonia mcp tools <server> [<tool>]` | Las descripciones de las herramientas y sus esquemas JSON. |
| `colonia mcp run <server> <tool> '<json>'` | Llama a una herramienta directo y muestra el resultado crudo; `-` lee los argumentos de stdin. |
| `colonia mcp check <server>` | Una prueba de conexión. |
| `colonia mcp signin <server>` | Iniciar sesión en un servidor que lo pidió; su página se abre en tu navegador. |
| `colonia extensions` | Las extensiones instaladas. |
| `colonia extensions inspect <folder>` | Qué traería una carpeta; no instala nada. |
| `colonia extensions install <folder>` | La copia, apagada. |
| `colonia extensions on <id>` | La prende (`off` la apaga). |
| `colonia extensions secret <id> <name>` | Le da un secreto, con el valor por stdin (`--clear` lo borra). |
| `colonia extensions rm <id>` | La saca. |
| `colonia clients` | Las apps externas con un token propio. |
| `colonia clients add <name>` | Un token para una (se muestra una vez), `--scopes chat,browser` (por defecto `chat`). |
| `colonia clients rm <id>` | Lo revoca. |
| `colonia secrets [list]` | Los nombres de los secretos y cuándo cambiaron (nunca los valores). |
| `colonia secrets set <name>` | Guarda un secreto; el valor llega por stdin. |
| `colonia secrets rm <name>` | Lo borra. |

`colonia mcp tools`, `run` y `check` aceptan `--project <id>` y `--scope global` o `--scope project`. Las llamadas MCP
directas son operaciones tuyas: no arrancan un turno de un agente.

Los valores nunca van en la línea de comandos, donde quedarían en el historial de tu shell:

```bash
printf '%s' "$KEY" | colonia secrets set gemini
```

### colonia como servidor MCP

| Comando | Qué hace |
|---|---|
| `colonia mcp` | Un servidor MCP por stdio con las herramientas `browser_*`, para Claude Code, Codex y otros clientes (`--by <agent>` dice quién lo usa). Con `COLONIA_CLIENT_TOKEN` además ofrece `colonia_agents`, `colonia_ask` y `colonia_read`. |
| `colonia mcp --run` | Las herramientas de una corrida de un agente, para un harness externo (lee `COLONIA_RUN_TOKEN`). Lo usa Colonia mismo. |

```bash
colonia clients add claude-code
claude mcp add colonia -e COLONIA_CLIENT_TOKEN=<token> -- colonia mcp
```

Más en [Clientes de afuera](/es/extend/outside-clients/).

## Entorno

| Variable | Por defecto | Qué hace |
|---|---|---|
| `COLONIA_URL` | `http://127.0.0.1:7440` | El core con el que habla esta terminal. El puerto sigue a `COLONIA_PORT`, después a `core.env`. |
| `COLONIA_TOKEN` | el de `<home>/core.env` | El token del core, para un core que lo pide. |
| `COLONIA_HOME` | `~/.colonia/v2` | La carpeta de Colonia: donde se lee y se escribe `core.env`. |

Los comandos que necesitan un secreto lo leen del entorno o de stdin, nunca de los argumentos: `COLONIA_CHANNEL_TOKEN` para
`colonia channels add`, `COLONIA_CLIENT_TOKEN` para `colonia mcp`. Todas las variables que lee el core están en
[Configuración](/es/reference/configuration/).

Un comando u opción desconocidos muestran un error corto y `Try: colonia --help`. Si el core está caído vas a ver
`colonia: the core is not running`; mira [Problemas frecuentes](/es/reference/troubleshooting/).
