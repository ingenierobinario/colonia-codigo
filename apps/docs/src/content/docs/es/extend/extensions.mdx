Una extensión es una carpeta con un `colonia-extension.json` que junta varias cosas: skills, servidores MCP, plantillas de
rutinas, los secretos que necesitan y, si hace falta, un plugin en un sandbox. Colonia lee el manifiesto sin correr nada,
la instala **apagada**, y encenderla aprueba exactamente los archivos que tenía.

## ¿Necesitas una?

Empieza por lo más pequeño que resuelva el problema:

| Quieres | Haz |
|---|---|
| Saber hacer algo para los agentes de un proyecto | Una [skill de proyecto](/es/extend/skills/) en `.apc/skills/` |
| Un servidor MCP más para tus agentes | `colonia mcps add` (mira [Servidores MCP](/es/extend/mcp/)) |
| Skills, servidores y rutinas que viajan juntos, para compartir o reusar | **Una extensión** |
| Código que mira eventos o suma contexto a tus turnos | Una extensión con plugin |

## Un ejemplo real: daily brief

El repositorio de Colonia trae `examples/extensions/daily-brief`: una skill y una rutina de días hábiles que la usa.

<FileTree>
- daily-brief/
  - colonia-extension.json
  - skills/
    - daily-brief/
      - SKILL.md
</FileTree>

```json title="colonia-extension.json"
{
  "id": "daily-brief",
  "name": "Daily brief",
  "version": "1.0.0",
  "description": "A short morning brief: open tasks, what is due, what others owe you.",
  "skills": "skills",
  "routines": [
    {
      "name": "Morning brief",
      "schedule": { "kind": "cron", "cron": "30 8 * * 1-5" },
      "prompt": "Use the daily-brief skill to write my morning brief."
    }
  ]
}
```

La skill le dice al agente que lea tus tareas y compromisos abiertos, escriba como mucho ocho líneas y conteste `SKIP`
cuando no hay nada que valga la pena decir (una rutina que contesta `SKIP` no le avisa a nadie).

## El manifiesto

El esquema es estricto: las claves desconocidas se rechazan.

| Campo | Qué lleva |
|---|---|
| `id` | Minúsculas, números, `_` y `-`, hasta 20 caracteres. |
| `name`, `version` | Obligatorios. `description` es opcional, hasta 500 caracteres. |
| `skills` | Una carpeta de carpetas de skills, cada una con su `SKILL.md`. |
| `mcp` | Servidores por nombre (letras, números y `_`): `command` + `args` + `env`, o `url` + `headers`. Un comando que empieza con `./` corre desde la carpeta de la extensión. |
| `routines` | Plantillas con `name`, `schedule` (`cron`, `every` cada N minutos con N de 5 o más, o `once`) y `prompt`. |
| `secrets` | Hasta 10, cada uno con `name`, `label` y una `url` opcional de dónde sacarlo. Cada valor lo escribes una vez. |
| `plugin` | Código opcional; mira más abajo. |

Un servidor MCP de una extensión solo puede usar los secretos **propios** de la extensión, como `secret://name`. No
puede nombrar tus otras variables ni el entorno, así que un paquete no puede llevarse tus credenciales a otro lado.

```json title="Un servidor MCP con su propio secreto"
"mcp": {
  "crm": { "command": "node", "args": ["./server.mjs"], "env": { "CRM_TOKEN": "secret://token" } }
},
"secrets": [{ "name": "token", "label": "CRM API token", "url": "https://example.com/settings/tokens" }]
```

## Instálala

<Tabs>
<TabItem label="Panel">

<Steps>

1. Abre **Recursos › Extensiones** y toca **Instalar**.

2. Pega la ruta de la carpeta, toca **Revisar** para ver qué trae, y después **Instalar**.

3. Llega apagada. Completa sus claves (**Editar**) y enciéndela.

4. Sus rutinas son sugerencias: **Añadir a Rutinas** pone una en Rutinas, apagada hasta que la enciendas.

</Steps>

</TabItem>
<TabItem label="Terminal">

```bash
colonia extensions inspect ~/work/daily-brief     # qué traería; no se instala nada
colonia extensions install ~/work/daily-brief     # se copia, apagada
colonia extensions secret <id> <name>             # el valor de un secreto declarado, por stdin (--clear lo borra)
colonia extensions on daily-brief
colonia extensions                                # las instaladas, encendidas o apagadas
colonia extensions off daily-brief
colonia extensions rm daily-brief
```

</TabItem>

Instalar copia archivos comunes a la carpeta de Colonia y les toma una huella. Si la copia instalada cambia en el disco,
Colonia apaga la extensión en el próximo arranque hasta que la vuelvas a aprobar. Para traer cambios de la carpeta
original, instálala de nuevo o usa **Volver a leer** en su detalle.

## Plugins

Cuando los archivos no alcanzan, una extensión puede traer un plugin: un archivo `.mjs` que corre en su propio
proceso, mira eventos (una tarea cambió, llegó un mensaje…) y puede sumar contexto a tus turnos.

```json
"plugin": { "entry": "plugin.mjs", "observe": ["task.updated"], "context": false, "network": false }
```

Corre en un sandbox con el modelo de permisos de Node: lee solo su carpeta, escribe solo su carpeta de datos, no
arranca procesos y no puede llamar a Colonia. Llega a internet solo con `"network": true`, y nunca a esta máquina. Lo que
suma como contexto le llega al agente como dato de fuera, no como instrucciones.

<Aside type="caution">
Una extensión con plugin corre código en tu ordenador. El panel te lo avisa antes de encenderla: hazlo solo si
confías en quien la hizo.
</Aside>

<Aside type="tip">
Colonia trae una skill `colonia-extensions` para Claude Code, Codex y otras apps de agentes, así le puedes pedir a una de ellas
que te arme una extensión. Mira [Skills](/es/extend/skills/#enseña-a-otras-apps-de-agentes-a-usar-colonia).
</Aside>
