Colonia is also an MCP server. Register `colonia mcp` in Claude Code, Codex or any other MCP client, and that app can ask your
Colonia agents things and drive Colonia's embedded browser.

## What the client gets

`colonia mcp` is a stdio MCP server that forwards to your running core. What it offers depends on the token it starts
with:

| Started with | Tools |
|---|---|
| No token | `browser_*`: tabs, open, navigate, snapshot, click, type, screenshot, text, history, handoff, close |
| A token with the **Chat** scope | `colonia_agents`, `colonia_ask`, `colonia_read` |
| A token with **Chat** and **Browser** | Both sets |

- `colonia_agents` lists your agents.
- `colonia_ask` asks one and waits up to 5 minutes for the answer. Pass the `thread` it returns to continue the chat.
- `colonia_read` reads a chat the client started.

The browser tools need the Colonia desktop app open, since it owns the browser. Password, one-time-code and card fields
are refused: `browser_handoff` hands the tab to you to log in.

## Create a token

Each app gets a token of its own. It's shown once; Colonia keeps only a fingerprint.

<Tabs>
<TabItem label="Panel">

In **Settings › API tokens**, type an **App name**, tick **Chat** and/or **Browser**, and press **Create token**.
Copy it right away. Each token shows when it was last used, and **Revoke** removes it.

<Shot name="settings-tokens" alt="Settings, API tokens: a list of app tokens with their scopes and last use, and a form to create a new one" caption="Settings › API tokens" />

</TabItem>
<TabItem label="Terminal">

```bash
colonia clients add claude-code                    # scope chat
colonia clients add codex --scopes chat,browser
colonia clients                                    # list, with last use
colonia clients rm <id>                            # revoke
```

</TabItem>
</Tabs>

<Aside type="caution" title="A token acts as a model, never as you">
An app with a token can only call what its scopes allow, and only in chats it started. Your agents treat its text as
a request from another app, not as your order, so a hijacked prompt in that app can't make them act as you. Keep the
token in the app's MCP settings, never in a repository, a prompt or `.apc/`.
</Aside>

## Register Colonia in your client

<Tabs>
<TabItem label="Claude Code">

```bash
claude mcp add colonia --scope user -e COLONIA_CLIENT_TOKEN=<token> -- colonia mcp
claude mcp add colonia-browser --scope user -- colonia mcp        # browser only, no token
claude mcp list
```

`--scope user` makes it available in every project.

</TabItem>
<TabItem label="Codex">

```bash
codex mcp add colonia --env COLONIA_CLIENT_TOKEN=<token> -- colonia mcp
codex mcp list
```

</TabItem>
<TabItem label="Other clients">

```json
{
  "command": "colonia",
  "args": ["mcp"],
  "env": { "COLONIA_CLIENT_TOKEN": "<token>" }
}
```

</TabItem>
</Tabs>

If `colonia` isn't on the client's PATH, use the full path that `command -v colonia` prints. For a core on another port or
machine, add `COLONIA_URL` to the environment too.

Then just ask, in Claude Code for example: "ask my Colonia secretary what's due this week". Or, with the browser scope:
"open the Acme Store admin in the Colonia browser and check today's orders".

## Teach the client about Colonia

Colonia copies a few skills into Claude Code, Codex, Cursor and `~/.agents` at every start, so those apps know how to use
`colonia` and these tools. See [Skills](/extend/skills/#teach-other-agent-apps-to-use-colonia).

## When the tools don't show up

<Steps>

1. Run `colonia status`: is the core running?

2. Run `colonia mcp` in a terminal. It should wait silently (Ctrl-C to quit). Any error here is the real one.

3. Only browser tools, no `colonia_*`: the token is missing or was revoked (`colonia clients`).

4. A token but no browser tools: its scopes leave the browser out (`--scopes chat,browser`).

5. Browser calls fail as unavailable: the desktop app isn't open.

</Steps>

<Aside type="note">
`colonia mcp --run` is a different thing, used inside Colonia's own runs. Don't register it in a client.
</Aside>
