`colonia` is the terminal for Colonia. It holds no logic of its own: every command is a call to the running core, the same
calls the panel makes. So anything you can do here you can also do in the panel, and the other way around for most
things.

`colonia --help` prints the full list. `colonia tasks help` and `colonia routines help` print the details of those two groups.

<Aside type="tip">
Placeholders in angle brackets are yours to fill in: `<id>` is an id from the matching list command (`colonia agents`,
`colonia threads`, `colonia tasks`…), `<agent>` an agent's id, `<project>` a project's id.
</Aside>

## The interactive console

Run `colonia` with no arguments in an interactive terminal (or `colonia wizard`) and you get a console with Tab completion and
history:

| Command | What it does |
|---|---|
| `/status` | Core, crew and projects (same as `colonia status`). |
| `/devices` | Paired devices. |
| `/tailscale` | Network access and Tailscale's state. |
| `/connect` | Expose Colonia through Tailscale. |
| `/pair` | A code to connect a new device. |
| `/updates` | Check for a newer Colonia. |
| `/panel` | The web panel's address. |
| `/help`, `/quit` | The menu again; back to your shell. |

The numbers `1` to `6` are shortcuts for the menu entries and `0` quits. Outside a terminal (a script, a pipe) the
console doesn't start: `colonia` prints the help instead.

## Status and maintenance

| Command | What it does |
|---|---|
| `colonia status` | The core's version and code commit, uptime, memory, URL, each subsystem, the crew, projects, MCP servers, devices, access and chats. Also `colonia --status`. |
| `colonia --version` | This CLI's version and commit (`-v`). Works without the core. |
| `colonia ping [text]` | A round trip over the live socket. |
| `colonia open` | Open the panel in your browser. |
| `colonia desktop` | Open the desktop app (it downloads and opens the installer the first time). |
| `colonia wizard` | Guided terminal setup and maintenance. |
| `colonia upgrade --check` | Is there a newer Colonia? |
| `colonia upgrade` | Apply it, the same as **Update now** in the panel. When the core does not answer, an Colonia installed with the install script updates itself anyway: it downloads the newest bundle, checks it and has the service start it. `colonia update` is the same command. |
| `colonia doctor` | Why the core does not answer on this computer (what its log says, the service, a newer release) and the one command to run next. Works without the core; `--json`. |
| `colonia logs` | The newest lines of the core's log, through the core: `-n 200`, `--level info\|warn\|error`, `--grep text`, `--scope core\|output`, `--json`. With no core answering, the file on this computer. |
| `colonia service logs` | The log file on this computer (`<home>/logs/core.log`); `-n 100`, `-f` to follow it. |
| `colonia daemon` | Explains which `colonia service` command to use (the background core is now a service). |
| `colonia --help` | The full list (`-h`). |

`colonia status`, `colonia devices`, `colonia tailscale status`, `colonia upgrade`, `colonia mcp tools`, `colonia mcp check` and `colonia memory`
take `--json`. `colonia status --plain` drops the card and the portrait.

## Service, access and devices

| Command | What it does |
|---|---|
| `colonia service install` | Run the core in the background: a systemd user unit (Linux), a launchd agent (macOS) or a login entry (Windows), started at login and again if it dies. |
| `colonia service status` | Whether the service is installed and running, and whether the core answers. |
| `colonia service restart` | Restart it (the core reads `core.env` when it starts). `colonia service start` does the same, or installs it when it is not installed yet. |
| `colonia service uninstall` | Remove the service. |
| `colonia expose tailscale` | Publish the core to your tailnet at `https://<machine>.<tailnet>.ts.net`; the core stays on loopback. |
| `colonia expose lan` | Listen on every network address of this machine. |
| `colonia expose off` | Only this computer again (the token stays). |
| `colonia expose status` | What is in effect, the port, the token (set or not), the settings file. |
| `colonia tailscale [status]` | Tailscale's state and the access mode, asked to the core. |
| `colonia tailscale connect` | Expose Colonia through Tailscale (must already be logged in). |
| `colonia tailscale off` | Back to local access. |
| `colonia pair` | A one-time code, the addresses and an `colonia://pair` link for a phone or another computer. |
| `colonia devices [list]` | Paired devices. |
| `colonia devices pair` | Same as `colonia pair`. |
| `colonia devices revoke <id>` | Revoke one device's key. |
| `colonia setup --headless` | A server with no desktop: service, optional import (`--import`), optional exposure (`--expose tailscale` or `--expose lan`), then a pair code. |
| `colonia import-v1` | Register the project folders a local Colonia v1 knows (read-only on v1). `--keys` also copies its model API keys, `--skills` its skills, `--services` its image engines and voices. |
| `colonia v1` | Is Colonia v1 still here and running? `colonia v1 off` stops its daemon for good so `colonia` is this one. |

`colonia expose` edits `<home>/core.env` directly; restart the core afterwards (`colonia service restart`). `colonia tailscale`
goes through the running core, which restarts itself when it runs under a supervisor such as the service, and
otherwise tells you to restart it. More in [Run Colonia on a server](/devices/server/).

## Chats and runs

| Command | What it does |
|---|---|
| `colonia chat "<text>"` | Talk to Home (the secretary) and print the answer as it builds: tool steps, sub-threads, widgets, questions. |
| `colonia chat "<text>" --agent <id>` | Talk to an agent, in its latest conversation with you (`--new` starts another). |
| `colonia chat "<text>" --thread <id>` | Write in a specific thread. |
| `colonia chat "<text>" --code` | A code thread in the registered project that holds the current folder (`--cwd <folder>` for another, `--write ask`, `auto` or `read-only`, `--agent <id>`). |
| `colonia threads [list]` | Threads with their state and kind. |
| `colonia threads get <thread>` | A thread's last 20 messages. |
| `colonia threads search <words…>` | Messages with every word, best match first. |
| `colonia threads cancel <thread>` | Stop what is running in it. |
| `colonia runs get <run>` | One run, as JSON. |
| `colonia runs wait <run>` | Wait for it to end (`--timeout 60`, in seconds). |
| `colonia runs pending [thread]` | What agents are waiting on from you: confirmations and questions. |
| `colonia runs respond <input> approve` | Approve (or `deny`), with an optional note and `--scope once`, `session` or `always`. |
| `colonia runs respond <input> "<answer>"` | Answer a question. |
| `colonia jobs [list]` | Background work running now and the last 10 finished. |
| `colonia jobs get <job>` | A job's state and output. |
| `colonia jobs cancel <job>` | Stop it. |
| `colonia compact <thread>` | Summarize a thread's older turns now (Colonia's own loop). |
| `colonia notifications` | What is waiting for you. |
| `colonia notifications read` | Mark everything read. |
| `colonia news` | Release news Colonia carries: told yet, and whether it applies to you. |
| `colonia news tell [id…]` | Tell news now (the given ones again, or the untold ones that apply), in your super-agent's words. |

`colonia chat` also takes `--detach` (send and return without waiting), and `--interrupt` or `--steer` for when the agent
is already working (stop it, or slip the message into the running turn). Without them the message waits its turn.

<Terminal command={`colonia chat "What is open in Acme Store?"`}>{`  ✓ List tasks
Two tasks are open in Acme Store: the spring catalog (in progress, Lucía) and the shipping rates (waiting for you).
— completed · thread home`}</Terminal>

## Agents and projects

| Command | What it does |
|---|---|
| `colonia agents` | Agents and the model each one runs on (★ marks Home). |
| `colonia agents show <agent>` | Its fields and full prompt. |
| `colonia agents new <slug> "<Name>"` | A new agent; `--project <id>` puts it in a project (written to `.apc/agents/<slug>.md`), `--role "<role>"` sets its role. |
| `colonia agents set <agent> key=value…` | Change any field the agent editor has (an unknown one lists them all). Lists as `tools=web_search,shell` (`tools=` is all of them), `orchestrator=true`, `rules='{"write":"ask"}'`; `autonomy=` or `rules=` go back to the default. |
| `colonia agents set <agent> --prompt-file <file>` | Replace its prompt from a file (`-` reads stdin). |
| `colonia agents limits [<agent> runs=… tokens=… \| <agent> clear \| default runs=… tokens=…]` | How far agents go without you in one chat: the default, and an agent's own budget (`0` = no limit). |
| `colonia agents clone <agent…>` | Copy agents into a project (`--project <id>`); `--rename` gives each a free name, `--under <slug>` sets the parent. |
| `colonia agents archive <agent>` | Archive an agent (a project agent's file moves to `.apc/agents/.archived/`). |
| `colonia agents archived` | Archived agents; `colonia agents restore <agent>` brings one back. |
| `colonia agents model <agent> <ref>` | Its model: `<engine>/<model>`, `<engine>`, `router` or `default`; `--router` keeps the router as its fallback. |
| `colonia projects [list]` | Projects (a `!` marks a folder that is missing). |
| `colonia projects register <folder>` | Register a folder with `AGENTS.md` and/or `.apc/`. |
| `colonia projects create "<Name>"` | A new project, in `--path <folder>` (made if missing) or a folder of its own in Colonia's home; `--kind personal\|app\|company\|software\|other`, `--desc "…"`. |
| `colonia projects set <project>` | Change `--name`, `--kind`, `--desc` or `--autonomy manual\|auto\|accept_edits\|plan\|total` (how far its agents go without asking). |
| `colonia projects folders list\|add\|rm <project> [folder]` | Folders its agents may read and never change (another checkout, docs): `file_read` and `shell` read there, nothing writes. |
| `colonia projects rm <project>` | Forget it in Colonia; its folder and files are never deleted. |
| `colonia init [folder]` | Make a folder (this one by default) an APC project and register it; writes only what is missing (`AGENTS.md`, `.apc/`). |
| `colonia projects sync [project]` | Read the project files again. |

## Models and usage

| Command | What it does |
|---|---|
| `colonia models` | Every engine and the models it offers (`--refresh` asks the engines again). |
| `colonia models config` | The install default, the router's chain and its rules. |
| `colonia models default <ref>` | The install default: `<engine>/<model>`, `<engine>` or `router` (`--router` to keep the router as fallback). |
| `colonia models chain <ref> [<ref>…]` | The router's fallback chain, in order. |
| `colonia models rules < rules.json` | The router's rules, as a JSON array on stdin. |
| `colonia usage [days]` | Turns and tokens by model over the last days (30 by default), and whether they were included in a plan or paid per token. |
| `colonia image "<prompt>"` | Draw an image and save it (`--out <file>`, `--size WxH`). |
| `colonia say "<text>"` | Speak text and save the audio (`--out <file>`). |
| `colonia transcribe <audio file>` | Speech to text. |
| `colonia owner [set key=value…]` | Who you are for your agents: name, about, language, timezone. |
| `colonia org [set] --project <id>` | A project's areas and roles (`set` reads JSON on stdin). |
| `colonia profiles [list]` | What the super-agent is for. `use <id> [key=value…]`, `off`, `restore <routine>`. |

See [Models](/concepts/models/) for what a model ref and the router are.

## Office

| Command | What it does |
|---|---|
| `colonia tasks` | Open tasks by column (`--project <id>` for one project). |
| `colonia tasks add <title…>` | A new task: `--project <id>`, `--agent <id>` (assign it), `--due 2026-10-05`. With `--person <name> --owed me` or `--owed them` it's a commitment. |
| `colonia tasks commitments` | What you owe and what you are owed. |
| `colonia tasks move <id> <column>` | Move it to another column. |
| `colonia tasks done <id>` | Close it as done (also `drop` and `reopen`). |
| `colonia tasks say <id> <text…>` | Comment on it; an `@agent` in the text asks that agent there. |
| `colonia routines` | Routines and when they run next (`--project <id>`). |
| `colonia routines add <name> <prompt…> --agent <id>` | A new routine. Schedule with `--cron "30 8 * * 1-5"`, `--every 60` (minutes) or `--at <ISO date>`; none means by hand. Also `--project`, `--pre "<command>"`, `--post "<command>"`, `--call always`, `output`, `fails` or `never`. |
| `colonia routines run <id>` | Run it now. |
| `colonia routines on <id>` | Turn it on (or `off`). |
| `colonia routines rm <id>` | Remove it. |
| `colonia routines log <id>` | Its recent runs. |
| `colonia flows run <flow> ['<JSON>']` | Run a published flow now; a webhook flow takes the JSON as the body it gets. Not inside an agent's command. |
| `colonia flows stop <flow> <event>` | Stop a run that is going; a message or call already sent is left to look at. Not inside an agent's command. |
| `colonia memory [words]` | Notes agents keep, newest first, or the best matches for the words (`--project`, `--agent`, `--json`). |
| `colonia memory add [scope] <text>` | Add a note. The scope is `global`, `project` or `agent` (with `--project <id>` or `--agent <id>`); without one it follows those options, else `global`. |
| `colonia memory edit <id> <text…>` | Rewrite a note in place. |
| `colonia memory rm <id…>` | Remove notes. |

In a routine, the pre-command's output reaches the prompt where you write `{{pre_output}}`. More in
[Tasks](/office/tasks/), [Routines](/office/routines/) and [Memory](/concepts/memory/).

## Channels and contacts

| Command | What it does |
|---|---|
| `colonia channels` | Channels and their state. |
| `colonia channels add telegram <id> --agent <agent>` | Add a Telegram bot. The token comes from `COLONIA_CHANNEL_TOKEN`, never the command line. |
| `colonia channels rm <id>` | Remove a channel and its token. |
| `colonia channels outbox` | What was sent lately and how it went. |
| `colonia channels send <channel> <contact> <text…>` | Write to a contact yourself, in their chat on that channel. |
| `colonia channels recover <thread>` | Ask the channel again for files that never arrived in a chat (WhatsApp: your phone sends those messages again; it has to be online). |
| `colonia contacts` | People and their addresses. |
| `colonia contacts add <name…>` | Add a contact. |
| `colonia contacts block <id>` | Block a person (`unblock` to undo). |
| `colonia contacts rm <id>` | Remove a person. |
| `colonia pairing` | Strangers waiting for approval. |
| `colonia pairing me <code>` | This address is mine (the owner's). |
| `colonia pairing ok <code> [name…]` | Approve as a contact. |
| `colonia pairing no <code>` | Turn it down. |

Other channels (WhatsApp, Discord, Slack) are set up in the panel. See [Channels](/channels/overview/).

## Skills, MCP, extensions and secrets

| Command | What it does |
|---|---|
| `colonia skills [project]` | Skills agents can load. |
| `colonia skills on\|off <skill>` | Turn a skill on or off everywhere, or in one project (`--project <id>`). |
| `colonia skills save <skill>` | Create or replace a skill: its `SKILL.md` on stdin (`--project <id>`). |
| `colonia skills install-runtimes` | Refresh now the skills that teach Claude Code, Codex, Cursor and `~/.agents` to use Colonia (the core also does it at every start). `--dry-run` shows what would change. |
| `colonia mcps [list [project]]` | MCP servers, with their state and tool count. |
| `colonia mcps add <name> <command…>` | Add one of your own: a command with its arguments, or a URL. |
| `colonia mcps rm <name>` | Remove it. |
| `colonia mcps show <name>` | Its definition (variables show as `secret://NAME`, never their values). |
| `colonia mcps set <name> --env K=V` | Change only what you pass (`--env`, `--header`), keeping the rest. |
| `colonia mcps on\|off <server> --project <id>` | Turn one of your servers on or off inside a project. |
| `colonia mcps logs <server>` | What a server printed on stderr since the core started (`--project`, `-n 100`). |
| `colonia sessions projects codex\|claude` | Claude Code or Codex projects and chats on this computer. |
| `colonia sessions import codex\|claude <project>` | Bring them in as an Colonia project (`--only <id,…>`, `--name "…"`); also `digest`, `adopt` and `page`. |
| `colonia mcps trust <project> <server>` | Approve a server a project's `.apc/mcps.json` names (`untrust` to undo). |
| `colonia mcp tools <server> [<tool>]` | Tool descriptions and JSON schemas. |
| `colonia mcp run <server> <tool> '<json>'` | Call a tool directly and print the raw result; `-` reads the arguments from stdin. |
| `colonia mcp check <server>` | A connection test. |
| `colonia mcp signin <server>` | Sign in to a server that asked for it; its page opens in your browser. |
| `colonia extensions` | Installed extensions. |
| `colonia extensions inspect <folder>` | What a folder would bring; nothing is installed. |
| `colonia extensions install <folder>` | Copy it in, turned off. |
| `colonia extensions on <id>` | Turn it on (or `off`). |
| `colonia extensions secret <id> <name>` | Give it a secret, value on stdin (`--clear` removes it). |
| `colonia extensions rm <id>` | Remove it. |
| `colonia clients` | Outside apps with a token of their own. |
| `colonia clients add <name>` | A token for one (shown once), `--scopes chat,browser` (default `chat`). |
| `colonia clients rm <id>` | Revoke it. |
| `colonia secrets [list]` | Secret names and when they changed (never the values). |
| `colonia secrets set <name>` | Store a secret; the value comes on stdin. |
| `colonia secrets rm <name>` | Remove it. |

`colonia mcp tools`, `run` and `check` take `--project <id>` and `--scope global` or `--scope project`. Direct MCP calls
are your own operations: they don't start an agent turn.

Values never go on the command line, where they'd stay in your shell history:

```bash
printf '%s' "$KEY" | colonia secrets set gemini
```

### colonia as an MCP server

| Command | What it does |
|---|---|
| `colonia mcp` | A stdio MCP server with the `browser_*` tools, for Claude Code, Codex and other clients (`--by <agent>` names who is using it). With `COLONIA_CLIENT_TOKEN` it also offers `colonia_agents`, `colonia_ask` and `colonia_read`. |
| `colonia mcp --run` | The tools of one agent run, for an outside harness (reads `COLONIA_RUN_TOKEN`). Colonia uses it itself. |

```bash
colonia clients add claude-code
claude mcp add colonia -e COLONIA_CLIENT_TOKEN=<token> -- colonia mcp
```

More in [Outside clients](/extend/outside-clients/).

## Environment

| Variable | Default | What it does |
|---|---|---|
| `COLONIA_URL` | `http://127.0.0.1:7440` | The core this terminal talks to. The port follows `COLONIA_PORT`, then `core.env`. |
| `COLONIA_TOKEN` | the one in `<home>/core.env` | The core's token, for a core that asks for one. |
| `COLONIA_HOME` | `~/.colonia/v2` | Colonia's home folder: where `core.env` is read and written. |

Commands that take a secret read it from the environment or stdin, never from arguments: `COLONIA_CHANNEL_TOKEN` for
`colonia channels add`, `COLONIA_CLIENT_TOKEN` for `colonia mcp`. Every variable the core reads is in
[Configuration](/reference/configuration/).

An unknown command or option prints a short error and `Try: colonia --help`. If the core is down you'll see
`colonia: the core is not running`; see [Troubleshooting](/reference/troubleshooting/).
